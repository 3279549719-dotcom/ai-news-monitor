1断点续跑别自研——有官方现成件，且要分两层

会话层用现成件：Claude Agent SDK（`resume(session_id)` / `continue` 一条语句接回上次会话，进程重启上下文不丢），或 LangGraph checkpoint（`thread_id` 快照 + SQLite/Postgres）。产物层用「文件系统即状态」：agent 每完成一个原子任务就把 PROGRESS.mdgit commit 写盘（官方 `commit-on-stop` 兜底）。两层都做才扛得住几小时长跑 + 随机断电。

→ 参考: anthropics/claude-agent-sdk · langchain-ai/langgraph · anthropics/cwc-long-running-agents

2长跑不跑偏靠「质量门」，不靠更长上下文

Anthropic 官方 `cwc-long-running-agents`（`/goal` 背后的最小实现）的质量闭环三原语：① Default-FAIL 契约——验收项从 `false` 开始，agent 必须先用 Read 看过证据（截图/日志）才允许标 pass（"没看证据不许说完成"）；② Fresh-context evaluator——无写权限的独立 subagent 审查 diff，返回 PASS/NEEDS_WORK，NEEDS_WORK 直接成为下一轮起始 prompt；③ Agent-maintained handoff——每个会话只做一个 feature，agent 自己写 PROGRESS.md。这正是你说的 G↔E 独立 loop 的官方验证版，可直接映射到 hooks。

→ 这就是「AI 挑自己的错不靠谱」的正解：评估器必须独立 + 无写权限 + 看证据

3网页壳不用从零造——现成三层可拼

界面层抄 OpenHands 的 React SPA（Agent Canvas：聊天 + Xterm 终端 + 文件树 + 浏览器四视图，事件流驱动刷新）；控制面参考 OpenClaw 的 Gateway 单点管全部会话 + 设备配对认证；会话层用 SDK 的 SessionStore adapter 把 transcript 镜像到共享存储实现跨进程恢复。轻量现成品也有：HolyClaude（docker 一键起）、`claudecode_webui`（包 Agent SDK + FastAPI + Vue3）、`claude-code-webui`（从 JSONL transcript 推导状态）。

→ 结论: 最小可用 = 网页壳(抄 OpenHands 交互) + 调度(claude-agent-sdk / claude -p) + 质量门(cwc 三原语)

📌 对本工作台的落地启示（方案 A 升级版）

断点续跑用 claude-agent-sdk 的 session 持久化（不用自研状态机）；质量闭环直接搬 cwc 三原语（Default-FAIL + 无写权限 evaluator + PROGRESS/git）；网页壳先抄 OpenHands 四视图交互，自研 ~50 行 Express 状态接口 + SSE 推进度。MetaGPT（一句话→软件仓库）是产品形态最接近的参照。重型方案（Temporal/trigger.dev/AgentOps/Letta）一致判为 过度工程，不碰。

五层自上而下；②③④是工作台要写的核心（薄壳），①抄 OpenHands 交互，⑤复用文档链模式。 断点续跑靠 ③session 落盘 + ⑤git 提交两层；跑偏靠 ④质量门收敛；乱花钱/危险动作靠 ② 门禁 + 网页批准。
