🧰 工具 vs 📋 上下文 Vibe Coder 版

“工具是手，上下文是大脑的工作台” —— 用 Claude 官方原话拆解这两个概念，让你写代码时不再迷糊。

🔧 工具 Tools

让 Agent 动起来的能力

💡 “10 个聚焦工具胜过 50 个重叠工具”
给 agent 一个 bash 常常比预建一堆工具更好。
  • 文件系统 — 最基础的持久化原语。读写文件、创建目录、移动数据。
  • Bash / Shell — 万能遥控器。安装依赖、运行脚本、管理进程。
  • 代码执行器 — 运行测试、执行代码片段、验证逻辑。
  • 搜索 / grep — 在代码库中快速定位，比遍历文件夹高效得多。

🎯 聚焦 ⚡ 直接 🧩 少而精

⚠️ 不是 MCP、不是 Skill、不是浏览器插件 —— 它们是 agent 可以直接调用的“动作”。

📋 上下文管理 Context Mgmt

让 Agent 记住该记住的

💡 “Compaction ≠ 够用”
长任务真正需要 Context Reset：清空窗口 + 靠结构化交接文件重建。
  • Compaction（就地总结） — 压缩历史对话，但 agent 仍带着“旧包袱”，容易焦虑。
  • Context Reset（重置） — 彻底清空，用交接文件（handoff artifact）把状态传给下一个 agent。
  • Skills 渐进式披露 — 按需加载，不让 agent 一开始就吞下整个说明书。
  • 结构化交接 — 把“当前进度 + 下一步计划”写进文件，让新 agent 无缝接盘。

🧠 记忆 🔄 重置 📦 交接

⚠️ 不是工具、不是代码逻辑 —— 它是 agent 的“工作记忆管理策略”。

⚖️ 它们到底有什么区别？

用一个比喻帮你刻进脑子：

🔧
工具 = 双手
  • ✋ 执行动作
  • 📂 操作文件
  • ⚙️ 运行命令
  • 🔍 搜索代码
🧠
上下文 = 工作台
  • 📋 记住什么
  • 🧹 清理什么
  • 📦 交接什么
  • 📖 按需加载什么
工具是“能力”，上下文是“状态管理”

📄 来自 Anthropic 官方原话解读

🗣️ “文件系统是最基础的持久化原语。”

→ 工具层：agent 通过读写文件来保存进度、传递数据，这是最原始也最可靠的方式。

🗣️ “10 个聚焦工具胜过 50 个重叠工具” + “给 agent 一个 bash 常常比预建一堆工具更好”

→ 工具设计原则：少而精，通用工具（如 bash）能覆盖大量场景，避免把简单的事搞复杂。

🗣️ “Compaction ≠ 够用。长任务真正需要 Context Reset：清空窗口 + 靠结构化交接文件重建。” + “Skills 的渐进式披露 = 按需加载”

→ 上下文管理：不仅仅是压缩对话，而是要有策略地重置和交接，让 agent 每次起步都清醒。Skills 按需加载避免了“信息过载”。

📌 一句话总结

工具 (Tools)
让 agent 做 事情 —— 读文件、写代码、运行测试、搜索。
上下文管理
让 agent 知道 自己在哪、该干什么、之前发生了什么 —— 通过重置、交接、按需加载。
它们的关系
工具负责“干活”，上下文负责“保持清醒”。
没有工具，agent 是空想家；没有上下文管理，agent 是健忘的苦力。

🎯 给 Vibe Coder 的最终提示

不要混淆： 工具 = 动作 上下文 = 记忆策略

MCP、Skill、浏览器插件 这些是 工具的具体实现 或 工具的载体，但“工具”这个概念本身，指的是 agent 能调用的任何能力单元。 而上下文管理，是让 agent 在长任务中 不迷路、不焦虑、不断片 的方法论。

💬 来自 Anthropic 工程师的实践：“Harness 设计，既选对工具，也管好上下文——两者缺一不可。”
